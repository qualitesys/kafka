19   /**
20    * The target state of a connector is its desired state as indicated by the user
21    * through interaction with the REST API. When a connector is first created, its
22    * target state is "STARTED." This does not mean it has actually started, just that
23    * the Connect framework will attempt to start it after its tasks have been assigned.
24    * After the connector has been paused, the target state will change to PAUSED,
25    * and all the tasks will stop doing work.
26    *
27    * Target states are persisted in the config topic, which is read by all of the
28    * workers in the group. When a worker sees a new target state for a connector which
29    * is running, it will transition any tasks which it owns (i.e. which have been
30    * assigned to it by the leader) into the desired target state. Upon completion of
31    * a task rebalance, the worker will start the task in the last known target state.
32    */
33   public enum TargetState {
34       STARTED,
35       PAUSED,
36   }
