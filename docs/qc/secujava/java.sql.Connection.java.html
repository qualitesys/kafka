46   /**
47    * <P>A connection (session) with a specific
48    * database. SQL statements are executed and results are returned
49    * within the context of a connection.
50    * <P>
51    * A <code>Connection</code> object's database is able to provide information
52    * describing its tables, its supported SQL grammar, its stored
53    * procedures, the capabilities of this connection, and so on. This
54    * information is obtained with the <code>getMetaData</code> method.
55    *
56    * <P><B>Note:</B> When configuring a <code>Connection</code>, JDBC applications
57    *  should use the appropriate <code>Connection</code> method such as
58    *  <code>setAutoCommit</code> or <code>setTransactionIsolation</code>.
59    *  Applications should not invoke SQL commands directly to change the connection's
60    *   configuration when there is a JDBC method available.  By default a <code>Connection</code> object is in
61    * auto-commit mode, which means that it automatically commits changes
62    * after executing each statement. If auto-commit mode has been
63    * disabled, the method <code>commit</code> must be called explicitly in
64    * order to commit changes; otherwise, database changes will not be saved.
65    * <P>
66    * A new <code>Connection</code> object created using the JDBC 2.1 core API
67    * has an initially empty type map associated with it. A user may enter a
68    * custom mapping for a UDT in this type map.
69    * When a UDT is retrieved from a data source with the
70    * method <code>ResultSet.getObject</code>, the <code>getObject</code> method
71    * will check the connection's type map to see if there is an entry for that
72    * UDT.  If so, the <code>getObject</code> method will map the UDT to the
73    * class indicated.  If there is no entry, the UDT will be mapped using the
74    * standard mapping.
75    * <p>
76    * A user may create a new type map, which is a <code>java.util.Map</code>
77    * object, make an entry in it, and pass it to the <code>java.sql</code>
78    * methods that can perform custom mapping.  In this case, the method
79    * will use the given type map instead of the one associated with
80    * the connection.
81    * <p>
82    * For example, the following code fragment specifies that the SQL
83    * type <code>ATHLETES</code> will be mapped to the class
84    * <code>Athletes</code> in the Java programming language.
85    * The code fragment retrieves the type map for the <code>Connection
86    * </code> object <code>con</code>, inserts the entry into it, and then sets
87    * the type map with the new entry as the connection's type map.
88    * <pre>
89    *      java.util.Map map = con.getTypeMap();
90    *      map.put("mySchemaName.ATHLETES", Class.forName("Athletes"));
91    *      con.setTypeMap(map);
92    * </pre>
93    *
94    * @see DriverManager#getConnection
95    * @see Statement
96    * @see ResultSet
97    * @see DatabaseMetaData
98    */

121       /**
122        * Creates a <code>PreparedStatement</code> object for sending
123        * parameterized SQL statements to the database.
124        * <P>
125        * A SQL statement with or without IN parameters can be
126        * pre-compiled and stored in a <code>PreparedStatement</code> object. This
127        * object can then be used to efficiently execute this statement
128        * multiple times.
129        *
130        * <P><B>Note:</B> This method is optimized for handling
131        * parametric SQL statements that benefit from precompilation. If
132        * the driver supports precompilation,
133        * the method <code>prepareStatement</code> will send

136        * not be sent to the database until the <code>PreparedStatement</code>

138        * affect which methods throw certain <code>SQLException</code> objects.
139        * <P>
140        * Result sets created using the returned <code>PreparedStatement</code>
141        * object will by default be type <code>TYPE_FORWARD_ONLY</code>
142        * and have a concurrency level of <code>CONCUR_READ_ONLY</code>.
143        * The holdability of the created result sets can be determined by
144        * calling {@link #getHoldability}.
145        *
146        * @param sql an SQL statement that may contain one or more '?' IN
147        * parameter placeholders
148        * @return a new default <code>PreparedStatement</code> object containing the
149        * pre-compiled SQL statement
150        * @exception SQLException if a database access error occurs
151        * or this method is called on a closed connection

177        * @param sql an SQL statement that may contain one or more '?'

179        * call escape syntax.
180        * @return a new default <code>CallableStatement</code> object containing the

201       /**
202        * Sets this connection's auto-commit mode to the given state.
203        * If a connection is in auto-commit mode, then all its SQL
204        * statements will be executed and committed as individual
205        * transactions.  Otherwise, its SQL statements are grouped into
206        * transactions that are terminated by a call to either
207        * the method <code>commit</code> or the method <code>rollback</code>.
208        * By default, new connections are in auto-commit
209        * mode.
210        * <P>
211        * The commit occurs when the statement completes. The time when the statement
212        * completes depends on the type of SQL Statement:
213        * <ul>
214        * <li>For DML statements, such as Insert, Update or Delete, and DDL statements,
215        * the statement is complete as soon as it has finished executing.
216        * <li>For Select statements, the statement is complete when the associated result
217        * set is closed.
218        * <li>For <code>CallableStatement</code> objects or for statements that return
219        * multiple results, the statement is complete
220        * when all of the associated result sets have been closed, and all update
221        * counts and output parameters have been retrieved.
222        *</ul>
223        * <P>
224        * <B>NOTE:</B>  If this method is called during a transaction and the
225        * auto-commit mode is changed, the transaction is committed.  If
226        * <code>setAutoCommit</code> is called and the auto-commit mode is
227        * not changed, the call is a no-op.
228        *
229        * @param autoCommit <code>true</code> to enable auto-commit mode;
230        *         <code>false</code> to disable it
231        * @exception SQLException if a database access error occurs,
232        *  setAutoCommit(true) is called while participating in a distributed transaction,
233        * or this method is called on a closed connection
234        * @see #getAutoCommit
235        */
236       void setAutoCommit(boolean autoCommit) throws SQLException;
