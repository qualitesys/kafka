27   /**
28    * {@code KGroupedTable} is an abstraction of a <i>re-grouped changelog stream</i> from a primary-keyed table,
29    * usually on a different grouping key than the original primary key.
30    * <p>
31    * It is an intermediate representation after a re-grouping of a {@link KTable} before an aggregation is applied to the
32    * new partitions resulting in a new {@link KTable}.
33    * <p>
34    * A {@code KGroupedTable} must be obtained from a {@link KTable} via {@link KTable#groupBy(KeyValueMapper)
35    * groupBy(...)}.
36    *
37    * @param <K> Type of keys
38    * @param <V> Type of values
39    * @see KTable
40    */

74        * user-specified in {@link StreamsConfig} via parameter
75        * {@link StreamsConfig#APPLICATION_ID_CONFIG APPLICATION_ID_CONFIG}, "storeName" is the
76        * provide store name defined in {@code Materialized}, and "-changelog" is a fixed suffix.
77        *

79        *

189        * Combine the value of records of the original {@link KTable} that got {@link KTable#groupBy(KeyValueMapper)
190        * mapped} to the same key into a new instance of {@link KTable}.
191        * Records with {@code null} key are ignored.
192        * Combining implies that the type of the aggregate result is the same as the type of the input value
193        * (c.f. {@link #aggregate(Initializer, Aggregator, Aggregator, Materialized)}).
194        * The result is written into a local {@link KeyValueStore} (which is basically an ever-updating materialized view)
195        * that can be queried using the provided {@code queryableStoreName}.
196        * Furthermore, updates to the store are sent downstream into a {@link KTable} changelog stream.
197        * <p>
198        * Each update to the original {@link KTable} results in a two step update of the result {@link KTable}.
199        * The specified {@link Reducer adder} is applied for each update record and computes a new aggregate using the
200        * current aggregate (first argument) and the record's value (second argument) by adding the new record to the
201        * aggregate.
202        * The specified {@link Reducer subtractor} is applied for each "replaced" record of the original {@link KTable}
203        * and computes a new aggregate using the current aggregate (first argument) and the record's value (second
204        * argument) by "removing" the "replaced" record from the aggregate.
205        * If there is no current aggregate the {@link Reducer} is not applied and the new aggregate will be the record's
206        * value as-is.
207        * Thus, {@code reduce(Reducer, Reducer, String)} can be used to compute aggregate functions like sum.
208        * For sum, the adder and subtractor would work as follows:

212        *     return currentAgg + newValue;
213        *   }
214        * }
215        *
216        * public class SumSubtractor implements Reducer<Integer> {
217        *   public Integer apply(Integer currentAgg, Integer oldValue) {
218        *     return currentAgg - oldValue;
219        *   }
220        * }
221        * }</pre>
222        * Not all updates might get sent downstream, as an internal cache is used to deduplicate consecutive updates to
223        * the same key.
224        * The rate of propagated updates depends on your input data rate, the number of distinct keys, the number of
225        * parallel running Kafka Streams instances, and the {@link StreamsConfig configuration} parameters for
226        * {@link StreamsConfig#STATESTORE_CACHE_MAX_BYTES_CONFIG cache size}, and

230        * {@link KafkaStreams#store(StoreQueryParameters) KafkaStreams#store(...)}:

233        * ReadOnlyKeyValueStore<K, ValueAndTimestamp<V>> localStore = streams.store(queryableStoreName, QueryableStoreTypes.<K, ValueAndTimestamp<V>> timestampedKeyValueStore());
234        * K key = "some-word";
235        * ValueAndTimestamp<V> reduceForWord = localStore.get(key); // key must be local (application state is shared over all running Kafka Streams instances)
236        * }</pre>
237        * For non-local keys, a custom RPC mechanism must be implemented using {@link KafkaStreams#metadataForAllStreamsClients()} to

560       /**
561        * Aggregate the value of records of the original {@link KTable} that got {@link KTable#groupBy(KeyValueMapper)
562        * mapped} to the same key into a new instance of {@link KTable} using default serializers and deserializers.
563        * Records with {@code null} key are ignored.
564        * Aggregating is a generalization of {@link #reduce(Reducer, Reducer) combining via reduce(...)} as it,
565        * for example, allows the result to have a different type than the input values.
566        * If the result value type does not match the {@link StreamsConfig#DEFAULT_VALUE_SERDE_CLASS_CONFIG default value
567        * serde} you should use {@link #aggregate(Initializer, Aggregator, Aggregator, Materialized)}.
568        * The result is written into a local {@link KeyValueStore} (which is basically an ever-updating materialized view)
569        * Furthermore, updates to the store are sent downstream into a {@link KTable} changelog stream.
570        * <p>
571        * The specified {@link Initializer} is applied once directly before the first input record is processed to
572        * provide an initial intermediate aggregation result that is used to process the first record.
573        * Each update to the original {@link KTable} results in a two step update of the result {@link KTable}.
574        * The specified {@link Aggregator adder} is applied for each update record and computes a new aggregate using the
575        * current aggregate (or for the very first record using the intermediate aggregation result provided via the
576        * {@link Initializer}) and the record's value by adding the new record to the aggregate.
577        * The specified {@link Aggregator subtractor} is applied for each "replaced" record of the original {@link KTable}
578        * and computes a new aggregate using the current aggregate and the record's value by "removing" the "replaced"
579        * record from the aggregate.
580        * Thus, {@code aggregate(Initializer, Aggregator, Aggregator, String)} can be used to compute aggregate functions
581        * like sum.
582        * For sum, the initializer, adder, and subtractor would work as follows:
583        * <pre>{@code
584        * // in this example, LongSerde.class must be set as default value serde in StreamsConfig
585        * public class SumInitializer implements Initializer<Long> {
586        *   public Long apply() {
587        *     return 0L;
588        *   }
589        * }
590        *
591        * public class SumAdder implements Aggregator<String, Integer, Long> {
592        *   public Long apply(String key, Integer newValue, Long aggregate) {
593        *     return aggregate + newValue;
594        *   }
595        * }
596        *
597        * public class SumSubtractor implements Aggregator<String, Integer, Long> {
598        *   public Long apply(String key, Integer oldValue, Long aggregate) {
599        *     return aggregate - oldValue;
600        *   }
601        * }
602        * }</pre>
603        * Not all updates might get sent downstream, as an internal cache is used to deduplicate consecutive updates to
604        * the same key.
605        * The rate of propagated updates depends on your input data rate, the number of distinct keys, the number of
606        * parallel running Kafka Streams instances, and the {@link StreamsConfig configuration} parameters for
607        * {@link StreamsConfig#STATESTORE_CACHE_MAX_BYTES_CONFIG cache size}, and
608        * {@link StreamsConfig#COMMIT_INTERVAL_MS_CONFIG commit interval}.
609        * For failure and recovery the store will be backed by an internal changelog topic that will be created in Kafka.
610        * The changelog topic will be named "${applicationId}-${internalStoreName}-changelog", where "applicationId" is
611        * user-specified in {@link StreamsConfig} via parameter
612        * {@link StreamsConfig#APPLICATION_ID_CONFIG APPLICATION_ID_CONFIG}, "internalStoreName" is an internal name
613        * and "-changelog" is a fixed suffix.
614        * Note that the internal store name may not be queryable through Interactive Queries.
615        *
616        * You can retrieve all generated internal topic names via {@link Topology#describe()}.
617        *
618        * @param initializer a {@link Initializer} that provides an initial aggregate result value
619        * @param adder       a {@link Aggregator} that adds a new record to the aggregate result
620        * @param subtractor  a {@link Aggregator} that removed an old record from the aggregate result
621        * @param <VR>        the value type of the aggregated {@link KTable}
622        * @return a {@link KTable} that contains "update" records with unmodified keys, and values that represent the
623        * latest (rolling) aggregate for each key
624        */
