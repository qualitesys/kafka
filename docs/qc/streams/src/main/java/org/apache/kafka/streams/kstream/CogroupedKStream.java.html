29   /**
30    * {@code CogroupedKStream} is an abstraction of multiple <i>grouped</i> record streams of {@link KeyValue} pairs.
31    * <p>
32    * It is an intermediate representation after a grouping of {@link KStream}s, before the
33    * aggregations are applied to the new partitions resulting in a {@link KTable}.
34    * <p>
35    * A {@code CogroupedKStream} must be obtained from a {@link KGroupedStream} via
36    * {@link KGroupedStream#cogroup(Aggregator) cogroup(...)}.
37    *
38    * @param <K> Type of keys
39    * @param <VOut> Type of values after agg
40    */
41   public interface CogroupedKStream<K, VOut> {
42   
43       /**
44        * Add an already {@link KGroupedStream grouped KStream} to this {@code CogroupedKStream}.
45        * <p>
46        * The added {@link KGroupedStream grouped KStream} must have the same number of partitions as all existing
47        * streams of this {@code CogroupedKStream}.
48        * If this is not the case, you would need to call {@link KStream#repartition(Repartitioned)} before
49        * {@link KStream#groupByKey() grouping} the {@link KStream} and specify the "correct" number of
50        * partitions via {@link Repartitioned} parameter.
51        * <p>
52        * The specified {@link Aggregator} is applied in the actual {@link #aggregate(Initializer) aggregation} step for
53        * each input record and computes a new aggregate using the current aggregate (or for the very first record per key
54        * using the initial intermediate aggregation result provided via the {@link Initializer} that is passed into
55        * {@link #aggregate(Initializer)}) and the record's value.
56        *
57        * @param groupedStream a group stream
58        * @param aggregator    an {@link Aggregator} that computes a new aggregate result
59        * @param <VIn> Type of input values
60        * @return a {@code CogroupedKStream}
61        */
62       <VIn> CogroupedKStream<K, VOut> cogroup(final KGroupedStream<K, VIn> groupedStream,
63                                               final Aggregator<? super K, ? super VIn, VOut> aggregator);

65       /**
66        * Aggregate the values of records in these streams by the grouped key.
67        * Records with {@code null} key or value are ignored.
68        * The result is written into a local {@link KeyValueStore} (which is basically an ever-updating materialized view)
69        * that can be queried by the given store name in {@code materialized}.
70        * Furthermore, updates to the store are sent downstream into a {@link KTable} changelog stream.
71        * <p>
72        * To compute the aggregation the corresponding {@link Aggregator} as specified in
73        * {@link #cogroup(KGroupedStream, Aggregator) cogroup(...)} is used per input stream.
74        * The specified {@link Initializer} is applied once per key, directly before the first input record per key is
75        * processed to provide an initial intermediate aggregation result that is used to process the first record.
76        * <p>
77        * Not all updates might get sent downstream, as an internal cache is used to deduplicate consecutive updates to the
78        * same key.
79        * The rate of propagated updates depends on your input data rate, the number of distinct keys, the number of
80        * parallel running Kafka Streams instances, and the {@link StreamsConfig configuration} parameters for
81        * {@link StreamsConfig#CACHE_MAX_BYTES_BUFFERING_CONFIG cache size}, and
82        * {@link StreamsConfig#COMMIT_INTERVAL_MS_CONFIG commit interval}.
83        * <p>
84        * To query the local {@link ReadOnlyKeyValueStore} it must be obtained via
85        * {@link KafkaStreams#store(StoreQueryParameters) KafkaStreams#store(...)}:
86        * <pre>{@code
87        * KafkaStreams streams = ... // some aggregation on value type double
88        * String queryableStoreName = "storeName" // the store name should be the name of the store as defined by the Materialized instance
89        * ReadOnlyKeyValueStore<K, ValueAndTimestamp<VOut>> localStore = streams.store(queryableStoreName, QueryableStoreTypes.<K, ValueAndTimestamp<VOut>> timestampedKeyValueStore());
90        * K key = "some-key";
91        * ValueAndTimestamp<VOut> aggForKey = localStore.get(key); // key must be local (application state is shared over all running Kafka Streams instances)
92        * }</pre>
93        * For non-local keys, a custom RPC mechanism must be implemented using {@link KafkaStreams#metadataForAllStreamsClients()} to query
94        * the value of the key on a parallel running instance of your Kafka Streams application.
95        * <p>
96        * For failure and recovery the store (which always will be of type {@link TimestampedKeyValueStore}) will be backed by
97        * an internal changelog topic that will be created in Kafka.
98        * Therefore, the store name defined by the Materialized instance must be a valid Kafka topic name and cannot
99        * contain characters other than ASCII alphanumerics, '.', '_' and '-'.
100        * The changelog topic will be named "${applicationId}-${storeName}-changelog", where "applicationId" is
101        * user-specified in {@link StreamsConfig} via parameter
102        * {@link StreamsConfig#APPLICATION_ID_CONFIG APPLICATION_ID_CONFIG}, "storeName" is a generated value, and
103        * "-changelog" is a fixed suffix.
104        * <p>
105        * You can retrieve all generated internal topic names via {@link Topology#describe()}.
106        *
107        * @param initializer  an {@link Initializer} that computes an initial intermediate aggregation
108        *                     result. Cannot be {@code null}.
109        * @return a {@link KTable} that contains "update" records with unmodified keys, and values that
110        * represent the latest (rolling) aggregate for each key
111        */
112       KTable<K, VOut> aggregate(final Initializer<VOut> initializer);
