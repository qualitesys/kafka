38   /**
39    * {@code KStream} is an abstraction of a <i>record stream</i> of {@link KeyValue} pairs, i.e., each record is an
40    * independent entity/event in the real world.
41    * For example a user X might buy two items I1 and I2, and thus there might be two records {@code <K:I1>, <K:I2>}
42    * in the stream.
43    * <p>
44    * A {@code KStream} is either {@link StreamsBuilder#stream(String) defined from one or multiple Kafka topics} that
45    * are consumed message by message or the result of a {@code KStream} transformation.
46    * A {@link KTable} can also be {@link KTable#toStream() converted} into a {@code KStream}.
47    * <p>
48    * A {@code KStream} can be transformed record by record, joined with another {@code KStream}, {@link KTable},
49    * {@link GlobalKTable}, or can be aggregated into a {@link KTable}.
50    * Kafka Streams DSL can be mixed-and-matched with Processor API (PAPI) (c.f. {@link Topology}) via
51    * {@link #process(ProcessorSupplier, String...) process(...)},
52    * {@link #transform(TransformerSupplier, String...) transform(...)}, and
53    * {@link #transformValues(ValueTransformerSupplier, String...) transformValues(...)}.
54    *
55    * @param <K> Type of keys
56    * @param <V> Type of values
57    * @see KTable
58    * @see KGroupedStream
59    * @see StreamsBuilder#stream(String)
60    */
