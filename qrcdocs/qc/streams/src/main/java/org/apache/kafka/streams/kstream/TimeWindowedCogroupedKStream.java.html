31   /**
32    * {@code TimeWindowedCogroupKStream} is an abstraction of a <i>windowed</i> record stream of {@link KeyValue} pairs.
33    * It is an intermediate representation of a {@link CogroupedKStream} in order to apply a windowed aggregation operation
34    * on the original {@link KGroupedStream} records resulting in a windowed {@link KTable} (a <emph>windowed</emph>
35    * {@code KTable} is a {@link KTable} with key type {@link Windowed Windowed<K>}).
36    * <p>
37    * The specified {@code windows} define either hopping time windows that can be overlapping or tumbling (c.f.
38    * {@link TimeWindows}) or they define landmark windows (c.f. {@link UnlimitedWindows}).
39    * <p>
40    * The result is written into a local {@link WindowStore} (which is basically an ever-updating
41    * materialized view) that can be queried using the name provided in the {@link Materialized} instance.
42    * Furthermore, updates to the store are sent downstream into a windowed {@link KTable} changelog stream, where
43    * "windowed" implies that the {@link KTable} key is a combined key of the original record key and a window ID.
44    * New events are added to windows until their grace period ends (see {@link TimeWindows#grace(Duration)}).
45    * <p>
46    * A {@code TimeWindowedCogroupedKStream} must be obtained from a {@link CogroupedKStream} via
47    * {@link CogroupedKStream#windowedBy(Windows)}.
48    *
49    * @param <K> Type of keys
50    * @param <V> Type of values
51    * @see KStream
52    * @see KGroupedStream
53    * @see CogroupedKStream
54    */
55   public interface TimeWindowedCogroupedKStream<K, V> {

57       /**
58        * Aggregate the values of records in this stream by the grouped key and defined windows.
59        * Records with {@code null} key or value are ignored.
60        * The result is written into a local {@link WindowStore} (which is basically an ever-updating materialized view).
61        * Furthermore, updates to the store are sent downstream into a {@link KTable} changelog stream.
62        * <p>
63        * The specified {@link Initializer} is applied directly before the first input record (per key) in each window is
64        * processed to provide an initial intermediate aggregation result that is used to process the first record for
65        * the window (per key).
66        * The specified {@link Aggregator} (as specified in {@link KGroupedStream#cogroup(Aggregator)} or
67        * {@link CogroupedKStream#cogroup(KGroupedStream, Aggregator)}) is applied for each input record and computes a new
68        * aggregate using the current aggregate (or for the very first record using the intermediate aggregation result
69        * provided via the {@link Initializer}) and the record's value.
70        * Thus, {@code aggregate()} can be used to compute aggregate functions like count or sum etc.
71        * <p>
72        * The default key and value serde from the config will be used for serializing the result.
73        * If a different serde is required then you should use {@link #aggregate(Initializer, Materialized)}.
74        * Not all updates might get sent downstream, as an internal cache is used to deduplicate consecutive updates to
75        * the same window and key.
76        * The rate of propagated updates depends on your input data rate, the number of distinct keys, the number of
77        * parallel running Kafka Streams instances, and the {@link StreamsConfig configuration} parameters for
78        * {@link StreamsConfig#STATESTORE_CACHE_MAX_BYTES_CONFIG cache size}, and
79        * {@link StreamsConfig#COMMIT_INTERVAL_MS_CONFIG commit interval}.
80        * <p>
81        * For failure and recovery the store (which always will be of type {@link TimestampedWindowStore}) will be backed by
82        * an internal changelog topic that will be created in Kafka.
83        * The changelog topic will be named "${applicationId}-${internalStoreName}-changelog", where "applicationId" is
84        * user-specified in {@link StreamsConfig} via parameter
85        * {@link StreamsConfig#APPLICATION_ID_CONFIG APPLICATION_ID_CONFIG}, "internalStoreName" is an internal name
86        * and "-changelog" is a fixed suffix.
87        * Note that the internal store name may not be queryable through Interactive Queries.
88        * <p>
89        * You can retrieve all generated internal topic names via {@link Topology#describe()}.
90        *
91        * @param initializer  an {@link Initializer} that computes an initial intermediate aggregation result. Cannot be {@code null}.
92        * @return a windowed {@link KTable} that contains "update" records with unmodified keys, and values that represent
93        * the latest (rolling) aggregate for each key within a window
94        */
95       KTable<Windowed<K>, V> aggregate(final Initializer<V> initializer);
